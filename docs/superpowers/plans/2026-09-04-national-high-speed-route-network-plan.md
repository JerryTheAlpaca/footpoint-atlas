# 全国高铁真实径路网络扩展计划

## Summary

- 从已验收的 `8740690` 新建 `codex/all-real-rail-routes`，保留宁蓉试点作为稳定基线；现有 14 个物理区段及其折线先做等价迁移，不重新调整已验收几何。
- 开始实施前，通过已登录的 `/api/train-data` 只读同步云端 38 条记录，并原子更新本地 Excel 与 `data.js`；云端版本作为验收基准，本地当前 37 条仅用于前期开发。
- 真实路径模式只处理 G/D/C 动车组。所有云端动车组记录必须能够自动寻径或通过少量覆盖解析；K/T/Z 等普速记录保留在数据中，但不在真实路径模式的地图、回放和地图关联记录列表中显示。
- 预置 11 条指定高铁主干、当前记录涉及的动车线路和必要联络线。今后在网站添加网络内车站的 G/D/C 行程时，无需再补坐标或线路数据。
- 精度目标是可信的线路级展示和估算里程，不追求站场咽喉、上下行线和短联络线的完全还原。

## Network and Data Changes

### 1. 可复现的数据构建

- 将现有单走廊脚本重构为“线路清单、车站节点、物理区段、状态日期、业务断言”驱动的全国网络构建器，继续生成离线 `window.RAIL_ROUTE_DATA`。
- 以固定的 [Geofabrik China OSM PBF](https://download.geofabrik.de/asia/china.html) 为主要几何来源，记录快照日期和校验值；PBF 与临时缓存不入库。Overpass 分窗查询仅用于补缺，OpenRailwayMap 用于人工核验。
- 沿线每个客运站均建立稳定节点，相邻客运站之间拆成无方向物理区段；实际分岔处增加线路所/联络线节点。复线只选一条代表性中心线，重叠干线复用同一物理区段并通过 `lineIds` 标注多重归属。
- 保留复盘中已验证的 way 图 Dijkstra、连通分量筛选、候选端点配对、简化前里程计算和约 `0.0009°` 的显示折线简化。
- 新增生成期硬校验：端点到下一折点不得超过 2 km、相邻站必须连通、区段长度落入合理范围、无连续重复坐标、无重复物理区段、所有生成写入保持原子性。

### 2. 导入范围

| 批次 | 导入线路 | 主要用途 |
|---|---|---|
| A：东部与东北 | 京沪、京哈、沪宁城际、宁杭 | 北京、南京、上海、杭州及未来沿线站点 |
| B：南北主轴 | 京广、广深港 | 郑州、武汉、衡阳、广州、深圳、香港记录 |
| C：东西主轴 | 宁蓉、沪昆、徐兰、兰新 | 成都、武汉、长三角、西安、兰州、西宁方向 |
| D：京港通道 | 京雄、雄商、商合、合安九、昌九、昌赣、赣深及与广深港的衔接 | 建立京港方向完整拓扑 |
| E：现有记录补充线 | 湖杭、沪杭、杭黄、武孝城际、武黄/黄黄、安九、池黄及当前动车记录实际经过的连接区段 | 覆盖杭州西、临平南、天河机场、黄山西等非主干端点 |
| F：宁蓉复用 | 当前南京南—合肥—六安—麻城北—汉口/武汉网络 | 保持现有试点结果和热度统计不变 |

- 当前 38 条记录另建自动审计清单：根据日期、车次和停站序列验证自动结果。只有自动最短路确实走错并行通道时，才添加日期＋车次＋起终点覆盖；小型联络线不为视觉上不显著的差异增加大量特例。

### 3. 自动寻径和未来扩展

- 默认按记录日期过滤可用区段，再以物理里程运行 Dijkstra；精确覆盖优先，自动路径其次，未知站或断网时回退现有曲线。
- 提供最多三条候选路径；若第二条路径属于不同干线且长度不超过最短路的 1.25 倍，结果标记为 `ambiguous`，当前仍展示最短路径并在设置中计数提示。
- 本阶段不实现页面选径，也不扩展乘车记录结构；稳定的区段 ID、记录键和候选路径接口为后续页面选径及云端保存偏好预留兼容基础。
- 铁路网络节点同时作为网站添加行程时的车站词典：出发站和到达站提供沿线站名建议，网络内车站视为已有坐标，不再显示经纬度输入框，也不把整套铁路节点复制进云端 `stations` 数据。
- 新增网络外的 G/D/C 行程仍允许保存，在真实模式回退曲线并显示“待补径路”提示；新增普速行程只在曲线模式显示。

## Runtime, UI and Interfaces

- 扩展 `RAIL_ROUTE_DATA`：
  - `lines`：线路 ID、名称、起终点、状态和来源。
  - `nodes`：稳定 ID、标准站名、别名、类型及坐标。
  - `segments`：起终节点、`lineIds`、状态日期、简化折线、OSM 估算长度。
  - `overrides`：仅保存确有歧义的记录覆盖。
  - `source`：PBF/Overpass 快照、许可、构建版本和校验信息。
- 扩展纯函数接口：
  - `TrainRoutes.stationNames()` 返回可直接用于行程表单的网络车站。
  - `stationCoord()` 支持真实模式优先采用轨道节点坐标、曲线模式保持原坐标。
  - `resolveRecordRoute()` 返回 `segIds`、`points`、`km`、`resolution` 和歧义状态。
  - `findRouteCandidates(record, { limit: 3, maxRatio: 1.25 })` 为审计及后续页面选径提供候选。
  - 既有 `aggregateSegments`、`mileageSummary`、`coverageSummary` 保持兼容，由调用方传入 G/D/C 记录集合。
- 切换到真实路径模式时：
  - 有效记录强制限定为 G/D/C，普速按钮设置为 `disabled` 和 `aria-disabled`。
  - 若切换前正选中普速，则自动切换到动车；“全部”在此模式表示全部动车组。
  - 地图、时间轴和地图关联记录列表排除普速；顶部历史总数、排行榜和年度统计仍基于全部记录。
  - 返回曲线模式时恢复普速按钮和进入真实模式前的类别筛选。
- 设置文案改为“高铁真实路径”，显示“已解析/动车组总数、歧义数、曲线兜底数”；OSM 署名仅在该模式显示。
- 统计卡改名为“估算高铁里程”，重复乘坐重复累计。只有云端全部 G/D/C 记录都成功解析时显示；普速记录不影响完整性，新增网络外动车后自动隐藏。

## Test and Acceptance Plan

- 建立当前基线：现有 173 项 Node 测试和 29 项 Python 测试全部通过；各线路批次独立提交并在合并前完整回归。
- 数据测试覆盖：
  - 指定 11 条主干的每个客运站均为节点，相邻站可达，整条线路端到端连通。
  - 共享线路只保留一份物理区段；正反向坐标与区段顺序正确。
  - 状态日期有效，历史记录不会走入尚未开放的区段。
  - 宁蓉既有 14 区段、11 次记录解析结果及原热度表保持不变。
- 路由测试覆盖：
  - 云端 38 条记录全部保留，所有 G/D/C 记录满足 `matched === highSpeedRecords.length`；已知普速记录明确不参与覆盖率。
  - 为 G1970、G56、G65、D49、D5234、G1435、G2396、G254、D2294、广深港及京广相关记录建立线路级业务断言。
  - 每条主干至少验证一次中间站到中间站的未来新增行程，证明不依赖现有记录的起终点。
  - 验证覆盖优先级、日期过滤、候选排序、歧义标记、未知动车曲线回退和断网处理。
- UI 测试覆盖：
  - 真实模式不显示普速且不能点击普速筛选，返回曲线模式后恢复。
  - 网络内新车站无需输入坐标即可保存、回放和计算里程。
  - 估算高铁里程仅在动车组全覆盖时显示，加入未知动车后隐藏。
  - 桌面和手机检查全国网络加载、地图缩放、回放进度、共享区段热度、枢纽分支及设置提示。
- 生成完成后检查产物大小和首次解析耗时，确保全国数据仍以单个离线文件加载而不明显阻塞页面；最终重新核对分支指向、工作树和生成产物，防止后台构建造成提交漂移。

## Assumptions and Defaults

- “高铁列车”沿用项目现有定义，即车次以 G、D、C 开头；普速暂不制作真实径路。
- “沪蓉”按既有沪汉蓉客运通道处理；未来沪渝蓉新线以独立线路和状态日期管理，避免历史列车误走新线。
- 客运站级拓扑必须完整；站场内部、上下行差异、动车所和短联络线只需保证视觉连续与大方向正确。
- OSM 几何用于展示和估算，不代表客票计价里程；界面继续展示 OSM/ODbL 署名。
- 页面手动选择径路、把个人径路偏好写回云端以及普速网络建设均不在本分支范围内。
