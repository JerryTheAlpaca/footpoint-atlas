# 火车足迹移动端适配与滚动叙事计划

日期：2026-08-27  
状态：待实施

## 1. 概要

- 保留电脑端现有 1920×1080 大屏布局；视口宽度不超过 1024px 时切换为原生移动端布局，不再整体缩小页面。
- 手机端采用柔性分屏吸附，浏览顺序为：概览 → 地图回放 → 排行 → 缘分重逢 → 乘车记录。
- 动画采用克制的科技感风格，重点提升上下滑动时的层次感、连贯性和精致度，不牺牲内容可读性与操作效率。
- 手机端保留添加、编辑、删除、筛选、年度回顾和路线回放等完整功能。
- 本轮只处理界面、触控和动画，不修改现有访问方式、Docker 配置、数据结构、存储方式或服务端接口。

## 2. 响应式布局

### 2.1 桌面端

- 保留现有固定设计画布和等比缩放逻辑，避免电脑端布局、图表比例和视觉风格发生回退。
- 桌面端继续使用双栏仪表盘、侧栏排行和内部记录列表滚动。

### 2.2 手机和平板端

- 以 1024px 为紧凑布局断点，进入紧凑布局后清除 `.app` 的固定尺寸、绝对定位和内联缩放，恢复正常文档流。
- `html`、`body` 和 `.scale-stage` 改为允许纵向滚动，移除页面级 `overflow: hidden`。
- 使用 `100svh` 和 `env(safe-area-inset-*)` 处理手机地址栏、刘海屏和底部安全区。
- 页面重组为五个滚动场景：
  1. 标题、入口按钮和统计卡概览。
  2. 中国地图、筛选条件和时间轴回放。
  3. 车型、车站和路局排行。
  4. 缘分重逢汇总与详情。
  5. 乘车记录列表。
- 页面滚动容器使用 `scroll-snap-type: y proximity`，场景使用 `scroll-snap-align: start`，不使用强制逐屏锁定。
- 排行展开、缘分重逢详情、长记录列表和表单保持内容自然增高，避免吸附导致用户无法越过长内容。
- 统计卡、筛选器、按钮组和时间轴允许换行；乘车记录由三列改为单列。
- 所有主要触控目标不小于 44×44px；表单输入字号不小于 16px，避免 iOS 聚焦时自动放大页面。

## 3. 滚动动画

### 3.1 动画机制

- 新增轻量移动端动画控制脚本，使用原生 `IntersectionObserver` 判断当前场景，不引入第三方动画库。
- 只有脚本成功初始化后才启用动画初始状态，防止脚本失败或浏览器不支持观察器时内容不可见。
- 当前场景进入视口时添加激活状态；离开后恢复弱化状态，因此向上和向下滑动均能获得一致反馈。
- 滚动监听使用 `passive: true`，连续进度计算通过 `requestAnimationFrame` 合并到每一帧，避免高频布局抖动。

### 3.2 视觉效果

- 场景进入时采用约 500ms 的透明度渐显、约 20px 纵向位移和轻微缩放。
- 场景内部的标题、卡片和图表按约 60ms 间隔错峰进入，形成层次感但不拖慢浏览。
- 当前场景边框和背景光晕轻微增强，离开视口后降低亮度，不将内容完全隐藏。
- 仅装饰背景、扫描线或光晕产生不超过约 8px 的视差位移；文字、表单和图表主体保持稳定。
- 保留现有地图线路流光、车站涟漪、统计数字增长和排行榜增长动画，并与场景入场节奏协调，避免多套动画同时抢夺注意力。

### 3.3 减少动画

- 支持 `prefers-reduced-motion: reduce`。
- 开启减少动画后禁用视差、场景过渡、错峰入场、数字滚动和非必要图表动画。
- 减少动画只改变表现，不影响滚动、筛选、回放和数据维护功能。

## 4. 地图与图表适配

- 手机端地图默认不接管单指滑动，使用户从地图区域向上或向下滑动时仍可滚动页面。
- 地图区域增加“探索地图”按钮；用户进入探索模式后才启用地图缩放和拖动，并提供清晰的“退出地图”入口。
- 桌面端保持地图现有漫游行为，不增加额外操作步骤。
- `TrainMap.buildGeoOption` 增加向后兼容的交互配置，用于根据布局模式切换地图漫游状态。
- 布局断点、横竖屏、弹层和排行展开状态变化后，统一触发 ECharts 尺寸重算。
- 地图在移动端使用明确的最小高度，筛选条件允许多行排列；播放按钮、进度条和时间标签按窄屏重新分组。
- 排行图根据可用宽度调整标签留白、字号和图表高度，长车型名称仍需完整可辨或提供省略提示。

## 5. 触控与完整功能

### 5.1 乘车记录

- 保留点击记录触发单次路线回放的行为。
- 每张记录卡在移动端显示“更多”按钮，点击后打开底部操作面板，提供编辑和删除操作。
- 电脑端继续支持现有右键菜单；移动端不依赖右键、长按或悬停。
- 记录卡的地图联动增加点击、键盘焦点和触控状态，桌面悬停高亮继续保留。

### 5.2 年度回顾与设置

- 年度回顾在手机端改为底部弹层或近全屏面板，年份按钮可以横向滚动或自动换行。
- 添加和编辑行程表单改为单列布局，弹层内部允许滚动，提交操作保持清晰可见。
- 日期选择器宽度限制在手机可视范围内，并处理屏幕边缘、软键盘和底部安全区遮挡。
- 编辑、删除、筛选、回放和表单验证继续复用现有业务逻辑，不改变保存语义。

## 6. 接口与兼容性

- `TRAIN_DATA` 数据结构、保存 API、Excel 同步流程和服务端冲突检测保持不变。
- `TrainScale` 增加紧凑布局判断；移动端清除缩放，桌面端继续计算并应用等比缩放。
- 新增移动端布局变化事件，供地图和排行图在断点或方向变化后统一刷新尺寸。
- 新增的地图交互配置保持可选，未传入配置时继续使用现有桌面行为。
- 不修改 `compose.yaml`、`Dockerfile`、Nginx 配置、Python 服务或启动脚本。
- 直接打开静态页面、使用本地 Python 服务和现有 Docker 部署时，数据读写行为均保持原样。

## 7. 测试计划

- 保持现有 127 项自动化测试全部通过。
- 扩展缩放测试，覆盖紧凑布局判断、移动端清除缩放和桌面端缩放兼容。
- 扩展地图测试，覆盖移动端漫游关闭、探索模式开启和桌面默认行为。
- 扩展交互测试，覆盖记录“更多”按钮、底部操作面板以及点击操作不会误触发路线回放。
- 增加移动端静态布局测试，检查：
  - 移动端恢复页面纵向滚动。
  - 使用柔性分屏吸附而非强制吸附。
  - 应用安全区、单列表单和单列记录布局。
  - 长内容不会被固定高度裁切。
  - `prefers-reduced-motion` 下动画被正确关闭。
- 对新增和修改的 JavaScript 执行语法检查，并运行全部 Node 与 Python 测试。
- 现有部署安全测试必须保持通过，确认移动端适配未改变网络访问范围。

## 8. 验收标准

- 覆盖 360–1024px 的手机和平板视口，手机竖屏作为主要体验，横屏切换后布局和图表能够正确重算。
- 360px 宽度下不存在页面级横向滚动，标题、按钮、筛选器和表单字段不被裁切。
- 页面上下滑动时场景过渡连贯，快速连续滑动不闪烁、不明显掉帧，也不会阻止原生滚动。
- 地图默认不会截获页面纵向手势，进入探索模式后可以正常缩放、拖动和退出。
- 添加、编辑、删除、年度回顾、筛选和路线回放均可在触屏设备上完成。
- 长排行、缘分重逢详情、乘车记录和表单能够自然滚动，不被分屏吸附困住。
- 开启系统减少动画设置后，内容立即可见且全部功能可用。
- 电脑端布局、地图回放、排行、年度回顾和数据维护功能不得回退。

## 9. 范围边界

- 本计划只覆盖前端响应式布局、滚动动画、触控交互和相关兼容测试。
- 不包含局域网共享、公网部署、身份认证、访问控制或服务器运维调整。
- 不更改现有数据内容、Excel 文件、地图数据和业务统计口径。
