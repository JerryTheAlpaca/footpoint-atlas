# 宁蓉铁路网络与可切换地图模式试点

## Summary

- 从干净的 `main` 创建 `codex/real-rail-routes-pilot` 分支。
- 保留现有曲线模式，设置页新增“地图显示”，可切换：
  - `曲线`：保持当前全部贝塞尔曲线。
  - `真实路径优先`：已收录铁路网络自动寻径，未覆盖行程回退曲线。
- 默认使用曲线，偏好保存在当前浏览器；桌面和手机均可切换。
- 真实路径不再按当前乘车区间预制，而是建立“车站/线路所为节点、相邻节点间为物理区段”的可扩展铁路网络。

## Railway Network Data

- 使用 [Geofabrik 的 OpenStreetMap 中国数据快照](https://download.geofabrik.de/asia/china.html)提取轨道中心线，以 OpenRailwayMap 人工核验；保存实际快照日期和 OSM 来源信息。
- 网络节点包括：
  - 宁蓉试点范围内所有办理客运的车站，例如南京南、全椒、肥东、合肥南、合肥西、六安、金寨、麻城北、红安西、汉口、武汉。
  - 所有影响拓扑的线路所、接轨站和分岔点，例如长安集、雷麻店、横店东及京广高铁接入点。
  - 不办理客运且不影响分岔的越行站、货运站不单独建节点。
- 每两个相邻节点之间建立一个无方向物理区段，保存线路名称、折线、OSM 估算长度和可选人工长度覆盖。
- 双线铁路使用一条经人工核验的代表性中心线，不把上下行线拆成两条业务区段。
- 将所有网络中的客运站坐标同时登记到标准站点坐标源。以后添加“南京南→麻城北”等行程时，不再要求用户手工填写麻城北坐标。
- 线路几何简化仅用于前端显示；里程使用简化前的 WGS84 折线计算，避免因减少坐标点而低估距离。

## Routing and Rendering

- `resolveRecordRoute` 首先应用人工径路覆盖，否则根据起终站节点在已收录网络中按区段长度自动寻径。
- 人工覆盖优先级为“具体日期+车次+区间”高于“默认区间”，用于处理同站对不同车次走不同联络线的情况。
- 自动寻径支持任意已收录节点组合，因此未来新增麻城北、红安西、金寨等行程不需要新增整条路径配置。
- 起终站不在网络内或网络不连通时返回未匹配，由地图使用现有曲线，不猜测或隐藏行程。
- 真实路径模式下：
  - 基础图按最小物理区段聚合当前可见记录，正反向共同累计热度。
  - 同一轨道区段只绘制一次。
  - 记录悬停、选中和单次回放使用自动拼接后的完整折线。
  - 时间范围、列车类型筛选和时间轴推进都会重新计算当前物理区段热度。
- 曲线模式完全走原有构建逻辑，11 次试点行程也恢复为原来的曲线。
- 南京南—武汉自动路径必须经宁蓉网络到横店东，再转京广高铁至武汉；南京南—汉口则从横店东继续进入汉口。
- 真实路径图层显示时，在地图角落展示“铁路几何 © OpenStreetMap contributors · ODbL”，符合 [OSM 署名要求](https://wiki.openstreetmap.org/wiki/Legal_FAQ)。

## Settings and Interfaces

- 设置导航新增“地图显示”面板，提供二选一控件、模式说明及动态覆盖率，例如“真实路径已覆盖 11/37 次，其他行程将显示为曲线”。
- 恢复手机标题区的紧凑设置按钮；普通设置显示分类导航，添加或编辑行程时继续隐藏导航。
- 模式切换立即生效并写入独立 localStorage key：
  - 保留地图中心、缩放、筛选条件和时间轴位置。
  - 自动回放进行中时暂停在当前进度后重绘。
  - 单次行程播放进行中时结束该动画并按新模式恢复地图。
- 新增离线 `window.RAIL_ROUTE_DATA`：
  - `source`：来源、快照和许可。
  - `nodes`：稳定 ID、名称、别名、类型和坐标。
  - `segments`：相邻节点、所属线路、折线、估算长度和可选覆盖长度。
  - `overrides`：特殊行程对应的有序区段列表。
- 新增纯函数接口：
  - `TrainRoutes.stationCoord`
  - `TrainRoutes.resolveRecordRoute`
  - `TrainRoutes.aggregateSegments`
  - `TrainRoutes.mileageSummary`
  - `TrainRoutes.coverageSummary`
- 不修改 `TRAIN_DATA` 记录结构、Excel 列、保存 API或行程表单。
- 总里程独立于显示模式，按每次乘车的有效路径累计；只有全部记录都有真实路径时，才在“车型数”右侧显示“估算总里程”。试点阶段保持隐藏，移动端完整显示时采用 2×2 卡片布局。
- 不显示单次或区段里程。

## Test Plan

- 网络数据校验：
  - 所有客运站具有唯一名称或明确别名。
  - 区段端点存在、折线与节点坐标相接、长度为正、无重复连续坐标。
  - 网络在南京南、合肥南/合肥西、六安、麻城北、横店东、汉口/武汉之间连通。
- 自动寻径：
  - 南京南→麻城北无需显式区间配置即可解析，并在麻城北结束。
  - 麻城北→南京南正确反转区段。
  - 南京南→武汉经横店东转京广，南京南→汉口不进入武汉支线。
  - 合肥西→武汉经合武绕行接入长安集。
  - 精确车次覆盖优先于默认寻径；未知站和断路安全回退曲线。
- 当前 11 次行程的粗粒度分支累计仍应满足：

| 走廊范围 | 该范围内每个最小区段的乘坐次数 |
|---|---:|
| 南京南—合肥南 | 8 |
| 合肥南—长安集 | 9 |
| 合肥西—长安集 | 1 |
| 长安集—六安 | 10 |
| 六安—横店东 | 10 |
| 横店东—汉口 | 7 |
| 横店东—武汉 | 3 |

- 设置行为：
  - 无偏好或偏好损坏时默认曲线。
  - 模式刷新后保持且不污染乘车数据存储。
  - 手机端可进入地图显示面板。
  - 切换模式保持地图视角、筛选和时间轴状态。
- 显示与统计：
  - 曲线模式保持当前 37 次线路结果。
  - 真实路径模式聚合 11 次、其余 26 次回退曲线。
  - 11/37 时总里程卡隐藏，37/37 时显示，新增未知路径后重新隐藏。
  - 桌面和手机检查共线路段、长安集/横店东分岔、站点对齐及 OSM 署名。
- 完整回归当前 Node 143 项和 Python 29 项测试。

## Assumptions

- “沿线每个站”指所有可办理乘降的客运站；线路所仅在影响铁路拓扑时纳入。
- 显示偏好只保存在当前浏览器，不跨设备同步。
- OSM 几何不能证明历史列车当天的精确径路；自动寻径提供合理默认，特殊车次通过覆盖数据修正。
- 试点仍只保证当前 11 次行程真实路径覆盖，但铁路网络预先包含宁蓉走廊沿线客运站，使未来新增站点组合可直接工作。
